# YouGile Integration

Инкапсулирует специфику YouGile REST API v1 для проекта «Созвон → Задачи».
Цель — единообразная, идемпотентная запись задач без повторного изучения API.

## Базовое

- Авторизация: ключ API компании. Получается по email+пароль администратора через
  эндпоинт ключей. Хранить в переменной окружения `YOUGILE_API_KEY`, не в коде.
- Базовый URL: `https://ru.yougile.com/api-v2` (v2) либо v1 по документации проекта.
  Уточнять актуальную версию в https://yougile.com/media/docs.
- Все запросы — REST, JSON. Ошибки обрабатывать с ретраями (см. pipeline-conventions).

## Структура объектов (важно)

```
Компания → Проекты → Доски → Колонки → Задачи
```
- У задачи есть уникальный ID с префиксом проекта.
- Маршрут задачи определяется выбором проекта/доски/колонки.
- Перенос задачи между проектами не меняет её ID.

## Создание задачи

Минимум для создания: `title`, `columnId` (в какую колонку класть).
Опционально: `description`, подзадачи (чек-лист), стикеры.

Шаги:
1. Определить `columnId` целевой доски/колонки (из справочника проекта).
2. Создать задачу с `title` и `description`.
3. Навесить стикеры (исполнитель, контролёр, срок, приоритет).
4. Добавить чек-лист как подзадачи, если он есть.

## Стикеры (ключевой механизм YouGile)

Поля задачи кладутся НЕ как обычные поля, а как **стикеры**:
- **Исполнитель** → системный стикер «Исполнитель», значение = YouGile user ID.
- **Контролёр** → кастомный текстовый стикер «Контролёр» (создать один раз), значение = имя/ID.
- **Срок** → стикер «Дедлайн» с датой окончания (timestamp).
- **Приоритет** → стикер «Приоритет» (текстовый, состояния low/medium/high/urgent).

Важная особенность: **если указанного стикера или его состояния не существует, YouGile
создаёт его автоматически** при записи. Это упрощает первую настройку — не нужно заранее
заводить все стикеры. Но: полагаться на автосоздание только для кастомных текстовых стикеров;
системные (Исполнитель, Дедлайн) подключать к доске заранее.

## People lookup

`assignee` и `controller` приходят как ИМЯ (из декомпозиции), не как ID. Сопоставление
имя → YouGile user ID делает детерминированный скрипт по справочнику (см. people-lookup модуль),
НЕ этот скилл и НЕ LLM. Этот скилл получает уже готовый user ID.

Получить список пользователей компании — отдельный эндпоинт; использовать для наполнения
и сверки справочника.

## Идемпотентность (обязательно)

Запись в командный трекер необратима и видна всем. Повторный запуск НЕ должен плодить дубли.
Правило:
- Перед созданием проверить маркер «эта задача уже отправлена» (хранить external_id ↔ YouGile
  task ID в своей БД).
- Если задача уже записана — пропустить, не создавать повторно.
- Маркер ставить ТОЛЬКО после успешного ответа API.

## Чего не делать

- Не хардкодить ID проектов/досок/стикеров — брать из справочника/конфига.
- Не писать в трекер до одобрения менеджером (двухфазность пайплайна).
- Не передавать секреты в URL. Ключ — только в заголовках/окружении.
